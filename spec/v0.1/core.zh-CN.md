                        Ops Tool Spec (OTS) — 核心规范


摘要

   本文档规定运维类软件向自主调用方暴露的工具、这些工具所返回结果的结构，
   以及修改系统状态的工具得以执行的条件。

   本文档位于工具传输层（例如 Model Context Protocol）之上，不定义传输、
   发现与调用。

本文档的状态

   本文档为草案，不稳定。在 1.0 之前的任何小版本都可能引入破坏性变更。

   本文档发布于 <https://github.com/mxyg/ots>，公开维护。本文档不是任何
   标准化组织的产物。意见与实现报告经由该仓库接收。

   ★ 本文为中文译本，属参考性文本。规范性文本为英文版 core.md；
     两者有出入时，以英文版为准。

1.  引言

   工具传输层（例如 Model Context Protocol [MCP]）定义了软件如何向自主
   调用方暴露工具：传输、发现与调用。它不定义某一类软件应暴露哪些工具、
   这些工具返回什么，以及其中哪些可以在无人参与的情况下执行。

   本文档为运维类软件规定上述内容。运维类软件指观察或修改主机、网络与
   设备状态的软件。

   本文档不定义任何领域专用工具。领域规范在本文档给出的约束下定义之。

2.  约定与术语

2.1.  要求记法

   本文档中的关键词 "MUST"、"MUST NOT"、"REQUIRED"、"SHALL"、"SHALL NOT"、
   "SHOULD"、"SHOULD NOT"、"RECOMMENDED"、"MAY"、"OPTIONAL"，当且仅当以
   全大写形式出现时，按 BCP 14 [RFC2119] [RFC8174] 的规定解释。

   各项要求以 [OTS-n.m] 标号。标号在本文档各版本间保持稳定。被撤销的
   要求保留其标号并标注为已撤销。

2.2.  术语

   调用方      调用工具的智能体、程序或人。

   错误        表示工具未能判定某一状态的结构化结果。

   实现方      依本文档暴露工具的运维类软件。

   改动        对实现方自身缓存、日志与任务记录之外的状态所作的更改，
               涉及任何主机、网络或设备。

   操作者      经由实现方自身界面使用该实现的人。

   工具        实现方暴露的、具名且可单独调用的操作。

   判定        表示已判定某一状态的结构化结果，由判定码及其依据的取值
               构成。

   判定码      命名某一状态的稳定标识符。

3.  符合性

   实现方符合且仅符合下列之一：

   OTS-Read    满足本文档除第 7 节外的全部要求，且不暴露任何声明为
               "mutate" 的工具。

   OTS-Full    满足本文档的全部要求。

   [OTS-3.1]  实现方 MUST 声明其对齐的本文档版本及其主张的符合性类别。

   [OTS-3.2]  暴露了一个或多个声明为 "mutate" 的工具、却不满足第 7 节与
   第 11 节的实现方，MUST NOT 主张符合本文档的任何类别。

4.  工具声明

   [OTS-4.1]  每个工具 MUST 声明其类别为 "read" 或 "mutate" 之一。

   [OTS-4.2]  执行改动的工具 MUST 声明为 "mutate"。

   [OTS-4.3]  以观察为目的发送网络流量，包括 ICMP 探测、传输层探测、
   名称解析查询与媒体流请求，其本身不构成改动。效果仅限于此类发送的工具
   MUST 声明为 "read"。

   [OTS-4.4]  实现方 MUST 能够在全部声明为 "mutate" 的工具被停用的情况下
   运行，并继续提供全部声明为 "read" 的工具。

   [OTS-4.5]  实现方 MUST NOT 经由其工具暴露某项能力，若操作者无法经由
   实现方自身界面调用该能力、或无法观察到该能力已被调用。

5.  结果

5.1.  判定

   [OTS-5.1]  成功的工具结果 MUST 为结构化取值。

   [OTS-5.2]  工具结果 MUST NOT 仅以供人阅读的自然语言文字表达其判定。

   [OTS-5.3]  判定 MUST 携带判定码，以及作出该判定所依据的取值。

   [OTS-5.4]  实现方 MAY 在结果中附加一个已渲染的、供人阅读的字符串字段。
   调用方 MUST NOT 依赖该字段是否存在、其内容或其语言。

5.2.  判定码

   [OTS-5.5]  判定码 MUST 由小写 ASCII 字母、数字与连字符（U+002D）构成。

   [OTS-5.6]  判定码的含义 MUST NOT 在实现方的各版本之间发生变化。实现方
   若需表达与既有判定码不同的状态，MUST 引入新的判定码。

   [OTS-5.7]  实现方判定出的状态若无对应判定码，MUST 返回判定码 "unknown"
   连同其已获取的取值，且 MUST NOT 以自然语言文字替代判定码。

   [OTS-5.8]  判定码处于单一扁平命名空间。领域规范 MUST NOT 为其判定码
   添加前缀或以其他方式命名空间化，并自行负责避免与本文档及其他领域规范
   发生冲突。

6.  错误

   [OTS-6.1]  未能判定状态 MUST 报告为携带第 10.2 节所列代码的结构化错误，
   且 MUST NOT 报告为判定。

   [OTS-6.2]  成功判定出对象存在故障，属于判定，MUST 报告为判定。

   [OTS-6.3]  权限要求在尝试操作之前即可确定的，实现方 SHOULD 不作尝试而
   直接返回 "permission-required"。

7.  改动控制

   本节不适用于符合性类别 OTS-Read。

   [OTS-7.1]  执行改动之前，实现方 MUST 经由其自身界面，就该项具体改动
   取得操作者的批准。

   [OTS-7.2]  向操作者呈现的批准请求 MUST 说明将要作出的更改。

   [OTS-7.3]  实现方 MUST NOT 将调用方提供的任何取值视为操作者已批准的
   凭据。此类取值包括名为 "user_approved"、"confirmed"、"force"、
   "emergency" 的字段，以及声称已获批准的自由文本。

   [OTS-7.4]  实现方 SHOULD NOT 提供使调用方在后续改动中豁免 [OTS-7.1]
   的设置。

   [OTS-7.5]  实现方 SHOULD 在执行改动之前将其持久化记录，并 SHOULD 能在
   执行之后将其回退，使得批准与完成之间发生的中断留下可恢复的状态。

8.  长时操作

   [OTS-8.1]  工作时长可能超过调用方请求期限的工具，MUST 及时返回任务
   标识符，且 MUST NOT 在工作期间保持调用处于打开状态。

   [OTS-8.2]  暴露受 [OTS-8.1] 约束之工具的实现方，MUST 同时暴露用于查询
   任务进度、获取任务结果与取消任务的工具。

9.  版本

   [OTS-9.1]  在主版本 0 之内，任何小版本 MAY 引入破坏性变更。

   [OTS-9.2]  自 1.0 起，小版本 MUST NOT 移除既有要求或判定码，亦 MUST NOT
   更改二者的含义。

10.  注册考量

10.1.  判定码

   本文档定义一个与领域无关的判定码。

      unknown     到达了实现方没有对应判定码的状态。

   领域规范在 [OTS-5.8] 的约束下定义其余判定码。

10.2.  错误码

   本文档定义下列错误码。该集合是封闭的；新增需修订本文档。

      invalid-argument      请求格式不合法，或取值超出范围。

      not-supported         请求合法，但在本平台或本构建上不受支持。

      permission-required   实现方缺少该操作所需的权限。

      approval-required     改动正在等待操作者批准（第 7 节）。

      approval-denied       操作者拒绝了该项改动。

      unreachable           无法到达对象。

      timeout               操作未在其期限内完成。

      internal              实现方自身的缺陷。

11.  安全考量

   [OTS-11.1]  就 [OTS-7.1] 而言，实现方 MUST NOT 将调用方视为权威来源。

   调用方在运行过程中所读取的内容，包括设备标识信息、日志文件、抓取的
   报文、协议响应，以及由第三方撰写的配置，可能含有针对调用方的文字。
   因此，行为正确的调用方仍可能被诱导去请求对操作者不利的改动。
   [OTS-7.3] 与 [OTS-11.1] 用于约束此种诱导的后果。

   [OTS-11.2]  实现方 SHOULD 默认将其接口绑定至回环地址。

   [OTS-11.3]  将接口绑定至非回环地址的实现方，MUST 要求为此进行显式配置，
   并 MUST 在该接口上对调用方进行认证。

   [OTS-11.4]  实现方 SHOULD 持久化记录每一次工具调用、其调用方身份、
   其参数与其结果。

   依 [OTS-4.3] 声明为 "read" 的工具会向调用方指定的对象发送流量。实现方
   无法判定操作者是否有权探测某一对象；该判定仍属于操作者。
